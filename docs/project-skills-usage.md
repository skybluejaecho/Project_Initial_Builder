# Project Skills 사용 안내

프로젝트가 채택한 스킬 목록을 관리하고, 작업에 적합한 등록 스킬을 추천합니다. 등록과 설치, 세션 인식과 실행 성공을 구분합니다. 이 문서는 사용 안내이며 프로젝트 채택 목록이 아닙니다.

## 범위

| 요청 | 결과 | 기본 편집 대상 |
|---|---|---|
| 등록·수정·목록에서 제외 | 지정한 항목만 변경 | 기존 목록 문서 하나. 없으면 `docs/project-skills.md` |
| 작업별 추천 | 적합한 등록 후보와 이유·적용 범위·인식 상태 | 없음 |
| 상태 점검 | 출처·중복·참조와 현재 환경에서 확인한 상태 | 없음 |

기존 목록은 형식과 위치를 유지합니다. 같은 항목을 다시 등록해도 변경이 필요 없으면 쓰지 않습니다. 목록에서 제외해도 설치된 스킬은 지우지 않습니다. 추천만 요청하면 후보를 실행하지 않습니다.

자동 설치·업데이트·삭제, 인터넷에서 새 스킬 탐색, 버전 동기화, 사용 통계, 커밋·푸시는 기본 기능에 포함하지 않습니다. repo-bootstrap이나 특정 설치 도구 없이 사용할 수 있습니다.

## 설치

[배포 원본](../skills/project-skills/SKILL.md)이 있는 `skills/project-skills/` 폴더 전체를 아래에서 필요한 한 곳에 복사합니다. `SKILL.md`, `agents/`, `assets/`를 함께 보존합니다. 같은 경로에 기존 설치가 있으면 비교 없이 덮어쓰지 않습니다. 배포 원본 위치 자체는 자동 설치 위치가 아닙니다.

| 환경 | 개인 설치 | 프로젝트 설치 |
|---|---|---|
| Codex | `~/.agents/skills/project-skills/` | `.agents/skills/project-skills/` |
| Claude Code | `~/.claude/skills/project-skills/` | `.claude/skills/project-skills/` |

`~`는 사용자 홈입니다. Windows에서도 같은 폴더 구조를 사용합니다. 설치 후 대상 프로젝트에서 새 세션을 열어 스킬 인식을 확인합니다. 프로젝트 목록에 어떤 스킬을 등록하는 것만으로 이 설치 과정이 수행되지는 않습니다. Python·Node 패키지나 별도 서버는 이 스킬의 실행 의존성이 아닙니다.

## 사용 흐름

아래 예시는 터미널 명령이 아닌 에이전트 대화 입력입니다. Claude Code에서는 `$project-skills` 대신 `/project-skills`를 사용합니다.

### 프로젝트 도입: 사용할 스킬 등록

```text
$project-skills
이 프로젝트 목록에 repo-bootstrap을 등록해줘.
출처: https://github.com/skybluejaecho/Project_Initial_Builder/tree/main/skills/repo-bootstrap
협업 규칙·PR 양식 준비와 공통 AI 지침 점검에 사용하고,
일반 기능 개발과 PR 코드 리뷰에는 사용하지 않을 거야.
기존 목록과 팀 메모가 있다면 보존해줘.
```

확인된 이름·출처·프로젝트에서의 사용 시점을 기록합니다. 필요할 때만 제외 상황을 추가합니다. [최소 목록 예시](../skills/project-skills/assets/catalog-example.md)는 새 문서 작성 참고용이며, 예시 항목을 자동으로 채택하지 않습니다. 상대 출처의 기본 기준은 프로젝트 루트입니다. 기존 문서에 다른 기준이 있으면 그 기준을 유지합니다.

공유 문서에는 개인 절대 경로, 로컬 설치 상태, 최근 실행 시각을 기록하지 않습니다. 특정 버전을 팀에서 채택한다면 커밋에 고정된 URL을 출처로 적을 수 있지만 자동 설치·버전 일치는 보장하지 않습니다.

### 작업 시작: 후보 추천 후 선택

```text
$project-skills 이번 PR 양식 정리에 사용할 스킬을 추천만 해줘.
```

예상 보고 형태:

```text
추천: repo-bootstrap
이유: 등록된 사용 범위에 PR 양식 정리가 포함됩니다.
맡길 범위: 기존 양식을 보존하며 필요한 항목 보완.
상태: 현재 세션에서 인식 / 파일만 확인 / 미확인 중 근거에 맞는 상태.
```

보통 한 개를 추천하며 작업이 분리될 때만 두세 개를 제시합니다. 적합한 등록 항목이 없으면 없다고 보고합니다. 목록 자체가 없으면 그 사실을 알리고 문서를 자동 생성하지 않습니다. 사용할 스킬을 골랐다면 다음처럼 작업을 지정합니다.

```text
Codex: $repo-bootstrap 기존 PR 양식에서 검증 결과 항목만 보완해줘.
Claude Code: /repo-bootstrap 기존 PR 양식에서 검증 결과 항목만 보완해줘.
```

선택된 스킬을 사용할 수 있고 출처가 확인될 때 해당 환경의 방식으로 적용합니다. 추천 과정 자체는 후보 실행을 승인하는 요청이 아닙니다. 이미 선택한 스킬과 작업을 명확히 요청했다면 같은 선택을 반복해서 묻지 않습니다. 제품 자체의 다른 스킬 자동 선택을 끄거나 모든 작업에 추천 절차를 강제하지 않습니다.

### 팀 합류와 목록 정리

```text
$project-skills 프로젝트 목록의 출처와 현재 세션 인식 상태를 점검만 해줘.
```

```text
$project-skills 목록에서 repo-bootstrap을 제외해줘. 설치 파일은 유지해줘.
```

같은 이름으로 여러 출처가 등록돼 있으면 제외할 출처를 구분합니다. 조회·점검에서는 문제를 발견해도 자동 수정하지 않습니다.

## 상태와 검증의 한계

- **현재 세션에서 인식:** 현재 에이전트가 제공한 목록·인식 정보에서 대상 스킬을 식별했습니다.
- **파일만 확인:** 로컬 스킬 파일이 있지만 현재 세션의 인식 근거는 없습니다.
- **미확인:** 접근·출처·세션 정보가 부족합니다. 제한된 경로에서 못 찾았다는 뜻을 전역 미설치로 확대하지 않습니다.

인식은 실행 성공, 인증 정상, Codex·Claude 간 호환, 동일 버전을 보장하지 않습니다. Markdown 목록은 제품의 설치 설정이나 강제 정책이 아니며, 이 스킬은 에이전트가 따르는 작업 지침입니다. 변경 결과는 diff로 확인해야 합니다. 다른 에이전트의 상태는 해당 환경에서 별도로 확인합니다.

임시 프로젝트 검증 방법과 실제 결과는 [검증 기록](project-skills-validation.md)에 정리합니다. Claude 실행 검증은 사용자 요청으로 계속 보류합니다.

설치·명시적 호출과 자동 선택에 관한 제품별 근거는 [Codex 공식 문서](https://learn.chatgpt.com/docs/build-skills)와 [Claude Code 공식 문서](https://code.claude.com/docs/en/skills)를 참고합니다.
