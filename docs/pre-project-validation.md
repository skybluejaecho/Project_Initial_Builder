## 첫 PR 절차 리허설

3명 팀의 실제 생성 문서 네 개를 해시가 일치하도록 별도 임시 Git 저장소에 옮겼습니다. 다음 단계는 스킬이 자동으로 처리한 것이 아니라 안내를 받은 팀원의 후속 작업입니다.

1. 로컬 디스크에만 원격 역할의 bare 저장소를 만들고, 협업 문서가 있는 첫 커밋을 `main`에 푸시했습니다.
2. `docs/topic-options`로 분기해 대상 사용자·문제·추정 난이도를 담은 세 후보의 비교표와 회의 질문을 작성했습니다. 안내의 커밋 형식으로 이 파일을 커밋·푸시했습니다.
3. 원격의 `main...docs/topic-options` 비교에 작업 커밋 하나와 `docs/topic-options.md` 한 파일만 포함되는지 확인했습니다. 생성된 PR 양식으로 본문 초안을 작성하고 표의 세 행·세 기준과 남은 질문을 대조했습니다.

이는 PR을 열 수 있는 브랜치와 본문까지의 검증입니다. 실제 GitHub PR 개설, 사람의 승인, 머지, 브랜치 보호 설정은 수행하지 않았습니다.

## 재검증 방법과 한계

- 임시 실행 공간에 검증할 스킬 폴더 전체를 `.agents/skills/repo-bootstrap/`으로 복사하고 설정 대상 `project/`를 따로 둡니다. 빈 폴더 사례에는 스킬 설치 파일조차 대상 안에 넣지 않습니다. 기존 팀 사례는 README가 기여 안내를 참조하게 하고, 다른 위치의 PR 양식·기존 Claude 연결·미커밋 메모를 준비합니다.
- 새 Codex 세션에서 `$repo-bootstrap`을 명시하고 `project/`만 설정하도록 요청합니다. 기존 팀은 “원본에 빠진 내용만 추가”와 “파일은 편집하지 말 것”을 각각 새 복사본에서 실행합니다. 재실행과 점검도 새 세션에서 수행합니다. 파일 목록·SHA-256 및 Git 참조와 상태는 읽기 전용 관찰기로 비교했습니다.
- 최초 배치에서는 샌드박스가 실행 공간 밖의 스킬·관찰기를 읽을 수 없었고 한 호출은 모델 용량 오류로 종료됐습니다. 이 시도들은 성공 사례에서 제외했습니다. 개인 설치본이나 전역 설정을 바꾸지 않고 위 격리 구조로 재시도했습니다.
- 스킬 형식, 상대 문서 링크, Git 공백 검사도 통과했습니다. Claude 연결은 문서 참조만 확인했고 **Claude 실행 검증은 보류**했습니다.
