# Project Skills 검증 기록

검증일: 2026-10-26 (Asia/Seoul). 구현 커밋: `aba3c6b`. Windows의 Codex CLI `0.163.0-alpha.11.1`에서 임시 프로젝트 여섯 개와 독립된 새 세션 열 번으로 명시적 호출을 검증했습니다. Claude 실행 검증은 사용자 요청으로 계속 보류했으며 이번 작업에서 재시도하지 않았습니다.

## 설치와 실행 방식

각 임시 프로젝트의 `.agents/skills/project-skills/`에 구현 폴더 전체를 복사했습니다. 세 파일이 배포 원본과 바이트 단위로 일치함을 확인했습니다. 사용자 전역 설치·설정·인증·PATH는 변경하지 않았습니다. 임시 프로젝트는 Git 초기화 없이 사용했습니다.

프롬프트에는 `$project-skills`와 실제 요청을 넣었습니다. 스킬 본문이나 기대 정답을 프롬프트에 붙여 넣지 않았습니다. 프로젝트 밖 편집, 네트워크 요청, 설치, 커밋·푸시, 다른 에이전트 실행은 하지 않도록 요청했습니다. 읽기 전용 사례도 쓰기가 가능한 샌드박스에서 실행해 스킬의 무수정 동작을 확인했습니다.

```powershell
Get-Content -LiteralPath $promptFile -Raw -Encoding utf8 |
    & $codexBinary exec -C $projectRoot -s workspace-write `
        -c 'approval_policy="never"' --skip-git-repo-check `
        --ephemeral --json -o $finalFile - `
        1> $eventLog 2> $errorLog
```

이미 설치된 위 버전의 실행 파일을 절대 경로로 지정하고 기존 모델 설정을 사용했습니다. `$projectRoot`는 각 임시 프로젝트이며 프롬프트·로그·해시 스냅샷은 그 밖에 보관했습니다. 이 명령은 검증용이며 스킬 사용자가 실행해야 하는 의존성이 아닙니다.

## 입력 사례

- **기존 목록:** README가 `docs/team-skills.md`를 가리킵니다. 목록에는 프로젝트 루트 기준 출처, API 리뷰 항목, 사용자 메모·주석과 CRLF 줄바꿈이 있습니다. 별도 `notes.txt`도 보존 대상입니다.
- **추천 후보:** 테스트용 `api-contract-review`와 `layout-review`를 프로젝트 스킬 위치에 둡니다. 설명은 각각 API 하위 호환성과 화면 레이아웃 리뷰로 제한합니다. 실제 리뷰를 요청받을 때 결과 파일을 만들도록 본문에 적어 추천 중 실행 여부를 구별합니다.
- **점검:** 같은 이름으로 출처가 다른 API 스킬 두 개와 존재하지 않는 로컬 출처를 등록합니다. 다른 출처의 API 스킬은 레거시 전용 설명을 갖지만 목록의 용도는 더 넓게 적어 불일치도 확인합니다.
- **목록 부재:** 추천 가능한 스킬 파일은 있지만 채택 목록은 없습니다. 같은 초기 상태를 추천과 신규 등록에 각각 사용합니다.
- **파일만 존재:** `team-skills/release-proof/SKILL.md`를 목록에 등록하되 제품의 스킬 탐색 위치에는 설치하지 않습니다. README의 오래된 “목록 없음” 문구와 실제 목록이 다른 상황도 함께 확인합니다.

## 결과

| 새 세션의 요청 | 관찰 결과 |
|---|---|
| 기존 목록에 layout-review 등록 | 기존 경로에 해당 항목만 추가. 메모·기존 항목·CRLF 보존, 다른 파일 해시 동일 |
| 같은 내용으로 다시 등록 | 중복 추가 없음. 8개 파일의 목록·SHA-256 동일 |
| layout-review 용도 수정 + 출처를 지정한 API 항목 제외 | 요청한 두 변경만 목록에 반영. 메모·CRLF 유지, 설치된 스킬과 나머지 파일 보존 |
| API 응답 변경 전 사용할 스킬 추천 | api-contract-review 하나 추천. 등록 출처와 세션 인식 경로를 연결하고 실제 리뷰는 실행하지 않음. 8개 파일 동일 |
| 일본어 번역에 사용할 등록 스킬 추천 | 적합한 등록 스킬 없음으로 보고. 목록 밖 후보 추가·실행 없이 8개 파일 동일 |
| 출처·중복·인식 상태 점검 | 동명·다른 출처를 별개 항목으로 구분. 레거시 용도 차이와 끊어진 참조 식별. 9개 파일 동일 |
| 동명 API 항목을 출처 지정 없이 제외 | 두 출처 중 대상을 확인하고 임의 삭제하지 않음. 9개 파일 동일 |
| 목록 없는 프로젝트에서 추천 | 목록 부재를 보고. 설치된 스킬을 자동 채택하지 않으며 7개 파일 동일 |
| 목록 없는 프로젝트에서 layout-review 등록 | `docs/project-skills.md`만 생성. 예시의 repo-bootstrap을 자동 등록하지 않음. 기존 7개 파일 해시 유지 |
| 파일만 있는 release-proof 추천 | 용도상 추천하되 **파일만 확인**으로 표시. 즉시 실행 가능·실행 성공으로 단정하지 않고 9개 파일 동일 |

각 세션에서 설치된 `project-skills/SKILL.md`를 읽은 도구 호출과 종료 결과를 확인했습니다. 추천·점검에서는 명령 기록도 검토했고 후보의 결과 파일이 생성되지 않았습니다. 내용 확인을 위해 후보의 `SKILL.md`를 읽는 것과 그 작업을 실제 실행하는 것을 구분했습니다.

기존 파일을 다루는 사례는 부모 프로세스에서 파일 목록과 SHA-256을 직접 비교했습니다. 등록·수정·제외 사례는 변경 대상 내용과 메모·기존 항목·줄바꿈도 확인했습니다. 신규 생성 사례의 `docs/project-skills.md`는 Windows 하위 샌드박스 접근 제한으로 부모에서 직접 읽을 수 없었습니다. 이 사례만 세션 내부의 전체 파일 해시 출력·생성 이벤트·내용 출력으로 대조했고, 상위 프로세스의 불완전한 파일 열거를 “신규 파일 없음”으로 판단하지 않았습니다.

## 정적 검사와 한계

- `quick_validate.py`로 스킬 형식 검사를 통과했습니다.
- UTF-8, 내부 문서 참조, Codex 메타데이터 길이와 `git diff --check`를 확인했습니다.
- 기존 repo-bootstrap의 스킬 파일과 검증 기록은 변경하지 않았습니다.
- 위 사례에서 구현 수정이 필요한 결함은 발견하지 않았습니다. 동작 검증 결과에 근거하지 않은 추가 규칙이나 실행 스크립트는 넣지 않았습니다.

이 결과는 위 Codex 버전과 임시 프로젝트에서의 명시적 호출에 대한 확인입니다. 자연어 자동 선택, 선택한 후보의 실제 업무 수행, 원격 출처 인증·접근, 모든 프로젝트 형식, Claude의 인식·호출·실행을 검증한 것은 아닙니다. repo-bootstrap에서 확인한 Claude 인식 결과를 이 새 스킬의 검증 결과로 재사용하지 않습니다.

원시 로그와 임시 프로젝트는 저장소에 커밋하지 않았습니다. 재검증 시 위 입력 사례를 별도 임시 프로젝트에 준비하고, 단계별 요청 후 파일 목록·내용·해시와 실제 도구 기록을 비교하세요. 제품이 보고하는 세션 정보보다 강한 실행·인증 보장을 추론하지 않습니다.
