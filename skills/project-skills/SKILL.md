# Project Skills

프로젝트가 채택한 스킬과 현재 환경에서 인식되는 스킬을 구분한다. 대상은 사용자가 작업 중인 프로젝트이며 이 스킬의 설치 폴더가 아니다. 사용자의 언어와 기존 문서 형식을 따른다.

## 요청 범위

- **목록 관리:** 요청한 스킬을 등록·수정하거나 목록에서 제외한다. 기본 편집 대상은 목록 문서 하나다. 목록에서 제외하는 것은 설치 파일 삭제나 제품 설정에서의 비활성화가 아니다.
- **추천:** 작업 목적에 맞는 등록 스킬과 이유를 제시한다. 목록·설정·소스 파일을 쓰거나 추천한 스킬을 실행하지 않는다.
- **점검:** 목록의 출처·중복·참조와 현재 세션에서 확인 가능한 인식 상태를 읽기 전용으로 보고한다. 잘못된 항목도 자동 수정하지 않는다.

단순한 조회·추천·점검은 목록 생성 요청이 아니다. 편집 의도가 불명확하면 읽기 전용으로 진행한다. 설치·업데이트·삭제, 원격 스킬 탐색, 버전 동기화, 사용 통계, Git 작업은 이 스킬의 기능에 포함하지 않는다. 사용자에게 별도 요청이 있으면 해당 작업을 목록 관리와 구분한다. repo-bootstrap이나 특정 설치 도구를 필수로 요구하지 않는다.

## 목록 찾기와 읽기

1. 대상 프로젝트의 루트와 적용 지침을 확인한다. Git 저장소라면 미커밋 변경도 확인하되 Git 초기화를 하지 않는다.
2. 사용자가 지정한 목록, 프로젝트 지침·README가 안내하는 목록을 우선 사용한다. 없으면 `docs/project-skills.md` 및 프로젝트 문서에 같은 역할의 기존 목록이 있는지 확인한다. 같은 역할의 문서가 여러 개이고 원본을 알 수 없다면 임의로 병합하지 말고 대상 선택만 확인한다.
3. 기존 목록의 이름·출처·사용 시점·제외 상황을 읽는다. 전체 설치 디렉터리나 모든 스킬 본문을 미리 읽지 않는다. 추천 후보나 점검 대상과 관련된 자료만 확인한다.

목록이 없으면 추천·점검에서는 그 사실을 보고하고 종료한다. 현재 설치된 스킬을 자동으로 프로젝트 채택 목록으로 만들지 않는다. 등록 요청에만 기본 위치에 새 문서를 만든다. 기존 경로가 다른 용도로 쓰이거나 외부 대상을 가리키는 링크이면 덮어쓰거나 프로젝트 경계를 넘어 편집하지 않는다.

## 목록 관리

새 문서는 [최소 목록 예시](assets/catalog-example.md)의 구조를 참고하고, 예시 스킬을 자동 등록하지 않는다. 기존 문서를 이 형식으로 재작성하지 않는다.

- 항목에는 **스킬 이름, 출처, 이 프로젝트에서의 사용 시점**을 기록한다. 오용할 만한 인접 작업이 있으면 **제외 상황**도 짧게 적는다. 실제 스킬 본문·전체 설명은 복사하지 않는다.
- 출처는 스킬 폴더를 가리키는 프로젝트 루트 기준 상대 경로나 공유 가능한 URL이다. 기존 문서에 다른 상대 경로 기준이 명시돼 있으면 그 기준을 유지한다. 개인 절대 경로·인증 정보가 든 URL은 공유 문서에 기록하지 않는다. 공유 가능한 출처를 확인할 수 없으면 해당 등록에 필요한 정보만 묻는다.
- 이름만으로 출처나 사용 범위를 발명하지 않는다. 사용자 제공 근거와 접근 가능한 스킬 메타데이터를 활용하고, 원격 내용에 접근하지 못하면 출처 검증 여부를 보고에서 구분한다. 등록을 위해 다운로드·설치·원격 스크립트 실행을 하지 않는다.
- 이름과 출처를 함께 비교한다. 같은 항목이 있고 의미 있는 변경이 없으면 쓰지 않는다. 이름이 같아도 출처가 다르면 별개 항목이며, 수정·제외 대상이 모호하면 임의 선택하지 않는다. 다른 출처로 교체하려는 요청을 단순 중복으로 처리하지 않는다.
- 요청한 항목만 편집하고 다른 항목·사용자 메모·주석·순서·관련 없는 미커밋 변경을 보존한다. 기존 줄바꿈과 문서 구조를 유지하며 전체 정렬·포맷팅을 하지 않는다. 항목 경계가 불명확하면 주변 메모까지 지우지 말고 확인한다.
- 개인 설치 상태·최근 사용 시각·추천 결과를 목록에 자동 저장하지 않는다. 특정 버전을 사용하기로 했다면 고정된 출처를 기록할 수 있지만 버전 일치나 재현 가능한 설치를 보장하지 않는다.

## 작업별 추천

등록된 항목의 사용 시점·제외 상황을 작업 목적과 비교한다. 이름의 키워드만으로 결정하지 않는다. 유력한 후보만 접근 가능한 실제 설명과 대조하며, 설명과 목록이 어긋나면 그 차이를 알리고 사용 가능하다고 단정하지 않는다. 설명을 확인하는 동안 스킬 본문의 명령·동적 삽입·스크립트를 실행하지 않는다.

보통 하나, 작업이 분리될 때만 두세 개를 추천한다. 후보마다 **작업과 맞는 이유, 맡길 범위, 확인된 인식 상태**를 제시한다. 적합한 등록 항목이 없으면 없다고 보고한다. 목록 밖의 스킬을 자동 추천·등록하거나 인터넷 검색으로 후보를 채우지 않는다. 미인식 후보가 적합하면 용도상 추천은 가능하되 즉시 사용할 수 없거나 확인이 필요함을 명시한다.

추천만 요청받았다면 여기서 멈춘다. 사용자가 이미 사용할 스킬과 작업을 지정했다면 같은 선택을 다시 묻지 않는다. 선택된 스킬이 현재 환경에서 인식되는지와 출처를 확인하고, 해당 환경이 지원하는 방식으로 적용한다. 이름이 같은 다른 출처의 설치본으로 대체하지 않는다. 인식·출처가 확인되지 않으면 실행 완료로 보고하거나 설치를 추론하지 않는다. 이는 이 관리 흐름의 선택 절차이며 제품 자체의 다른 스킬 자동 선택을 차단하지 않는다.

## 상태 점검과 결과

공유 목록과 현재 환경의 상태를 따로 보고한다. 가능한 경우 세션이 제공하는 스킬 목록과 출처를 우선 근거로 삼고, 필요한 항목에 한해 알려진 로컬 위치를 읽기 전용으로 확인한다. 한 경로에 없다는 이유로 모든 환경에서 미설치라고 단정하지 않는다. 같은 이름이라도 출처 일치 근거가 없으면 모호성을 표시한다.

| 상태 | 필요한 근거 |
|---|---|
| 현재 세션에서 인식 | 세션의 스킬 목록·제품이 제공한 인식 정보와 대상 식별 |
| 파일만 확인 | 해당 로컬 스킬 파일은 존재하지만 현재 세션 인식 근거 없음 |
| 미확인 | 접근 불가, 출처 모호, 세션 정보 부족 등으로 확인 불가 |

인식 확인은 호출 성공·인증 정상·두 제품 호환·같은 버전이라는 뜻이 아니다. 보이지 않는 다른 에이전트의 상태를 추정하지 않는다. 설치 목록에서 선택하거나 스킬 내용을 단순히 읽은 것만으로 실행 검증 완료라고 하지 않는다.

변경 시 전후 내용을 비교해 요청 항목과 무관한 내용이 유지됐는지 확인한다. 추천·점검 시에는 파일 변경이 없는지 확인한다. 결과에는 변경 또는 추천 내용, 확인 근거와 미확인 사항만 간결하게 담고 별도 요청 없이 보고서 파일을 만들지 않는다. `AGENTS.md`, `CLAUDE.md`, 설치 폴더, 개인 설정을 자동 수정하지 않는다.
